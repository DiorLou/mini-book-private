# 整理 Mini Book 笔记

把对话重写为能脱离聊天记录独立阅读的知识笔记，并把笔记放入用户指定或语义最匹配的书籍、章节与 `toc.yml`。不要把一问一答原样复制成聊天实录。

## 工作流程

### 1. 收集有效上下文

- 读取当前任务中与目标疑问有关的用户提问、Codex 回答、代码、报错、命令输出、截图说明和后续澄清。
- 优先采用用户提供的事实；不得臆造未出现的运行环境、代码行为或结论。
- 若 Codex 原回答存在明显错误或已被后续信息推翻，以修正后的知识写入笔记，并简短标明容易产生的误解。
- 省略寒暄、工具操作流水、无关讨论和仅对本次执行有意义的信息。

### 2. 确定存放位置

将位置拆成四级：`书籍 / 大章节 / 小章节 / 笔记`。

1. 先检查仓库根目录及各书籍的 `myst.yml`、`toc.yml` 和现有 Markdown 文件，了解真实结构与命名风格。
2. 用户可分别指定已有或新建的书籍、大章节、小章节；混合情况也必须支持，例如“已有书籍 + 新大章节 + 新小章节”。
3. 用户明确指定时遵从指定。未指定时，根据主题匹配已有位置；只有一个明显匹配项时直接使用。
4. 存在多个实质性候选且错误归类代价较高时，列出候选并询问用户。没有合适位置时，提出一个简洁、专业的中文名称并新建。
5. “大章节”和“小章节”是目录层级，不强制等于单独文件。按照当前书籍的 `toc.yml` 能力和既有风格表达层级；笔记本身通常是 Markdown 文件。

新建书籍时，沿用仓库现有 MyST 书籍的最小结构和配置风格，至少创建书籍目录、`myst.yml`、`toc.yml`、入口页和首篇笔记。若仓库的统一构建脚本或门户显式枚举书籍，也同步加入；不要复制其他书籍的标题、标识符或发布路径。遇到发布路径、书名或标识符无法安全推断时再询问用户。

### 3. 设计笔记标题与层级

- 标题应直接指向核心知识。存在公认专有名词时，优先把专有名词放进笔记标题或小标题，例如“词法作用域：为什么闭包仍能访问外部变量”。
- 大章节表达知识领域，小章节表达稳定主题，笔记标题表达本次解决的具体问题。
- 避免“问题记录”“一些知识”“Codex 回答”等无法检索的标题。
- 文件名遵循目标书籍的现有风格；没有风格可循时，使用简短、跨平台安全的名称，并避免同名覆盖。

### 4. 重写为独立笔记

写作前读取 [references/note-standard.md](references/note-standard.md)，严格按其中的内容要素和示例化规则组织笔记。

必须做到：

- 先交代读者遇到了什么具体问题、在什么背景下产生疑问。
- 汇总用户提供的代码或其他背景，整理为一个生动但忠于事实的示例。
- 说明 Codex 用哪些知识解决问题，并突出“为什么”：底层机理、因果链、适用条件和边界。
- 首次出现的关键专有名词使用粗体强调，并紧接通俗解释；不要只堆定义。
- 将结论落回原问题，让读者看到知识如何解释示例中的现象。
- 必要时加入最小代码片段、对比或步骤；删除与理解无关的样板代码。
- 使用通俗、准确、紧凑的中文。读者不应需要回看原对话。

### 5. 写入并更新目录

- 创建或更新目标 Markdown 文件，保留用户已有内容；同主题笔记优先增补或整合，避免重复页面。
- 修改目标书籍的 `toc.yml`，把笔记挂到正确的大章节和小章节下，并保持现有缩进、顺序和字段风格。
- 保持文件为 UTF-8，避免因终端默认编码破坏中文。
- 不改动无关书籍、章节或用户文件。

### 6. 验证与交付

- 检查 Markdown 标题层级、内部链接、文件路径和 `toc.yml` 引用均有效。
- 若仓库已有轻量构建或校验方式，运行与目标书籍相称的验证；不要为简单笔记无故执行全量发布。
- 最终向用户说明笔记写入的书籍、大章节、小章节、文件路径，以及是否新建了书籍或目录层级。

## 用户指令示例

- “用这个技能把刚才关于交叉熵的问答整理到已有的《深度学习》里。”
- “新建一本《Python 调试》，在新大章节‘运行时错误’下建立小章节‘作用域’，整理当前对话。”
- “放到 finance 这本已有书里，大章节沿用‘金融基础’，小章节新建‘复利’。”
- “整理成笔记，位置你判断。”
